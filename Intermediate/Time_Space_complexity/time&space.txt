--------------
-> Iteration - number of times a loop runs
-> compare algorithms - number of iterations it takes
-> Asymptotic Analysis - The technique used to analyze an algorithm's performance as the input size grows
-> Big-O Notation - One notation used in asymptotic analysis to describe the upper bound (worst-case growth rate)

--------------
calculation of Big(O)
-> calculate iterations based on input size
-> ignore lower order terms (terms with the highest degree (highest power of n) are higher order terms, remaining all are lower order terms)
-> ignore constant coefficients

eg iteration: 100 * log base2 N + 2
lower order term - 2
constant coefficient - 100
ans O(Iteration) - log base2 N

--------------
why we ignore lower order terms
-> when the input is large comparing a lower order term will not majorily affect the growth of algorithm, so it is ignored.
-> as the input increases, impact of lower order term decreases
-> eg: 100 * log base2 N + 2 -- where adding 2 not majorily affect the growth of algorithm

--------------
why we ignore constant coefficients
-> coefficients affects the execution time but not the growth of algorithm, so it is ignored.
-> eg: 100 * log base2 N -- where multiplying 100 with log base2 N affects the execution time but not the growth of algorithm

--------------

Drawbacks of Big-O:
• Doesn't give exact execution time.
• Ignores constant coefficients.
• Ignores lower-order terms.
• Focuses only on large input sizes.
• Doesn't consider hardware/compiler effects.
• Doesn't measure memory usage (space complexity).

Amortized Time complexity
* The average time of an operation over a sequence of operations, even if some individual operations are expensive
* in most cases it will take O(1) and rest of cases it will take O(n)

Example: ArrayList

* Assume the initial capacity is 10.
* The first 10 insertions take O(1) each.
* When inserting the 11th element:
    • A new larger array is created.
    • Existing elements are copied to the new array.
    • The new element is inserted.
    • This insertion takes O(n).
* Since resizing happens only occasionally, the amortized time
  complexity of add() is O(1).

--------------

space complexity

* It is the maximum space(worst case) that is utilised at any point in time during running the algorithm
* we determine space complexity using Big O

eg:
func(int N) { // 4 bytes -- we ignore the parameter
    int x = N; // 4 byte
    int y = x * x; // 4 byte
    long z = x + y; // 8 byte
    int arr[N]; // 4 * N
    long l [N] [N]; // 8 * N * N
}

8N^2 + 4 N + 16 => space complexity is O(N^2)
